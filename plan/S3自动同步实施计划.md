# MKnote S3 自动同步实施计划

- 日期：2026-07-22
- Owner：MDnote 开发者 / Codex
- 状态：实现完成，等待双设备人工验收
- 目标：在不阻塞本地编辑的前提下，自动同步默认笔记、默认 Quick Pocket 和 Quick Todo；网络失败可恢复，多设备并发修改不静默丢数据。

## 1. 决策摘要

本计划采用“本地优先 + 后台自动同步 + 版本检测 + 冲突保留”的模式。

- 使用官方 Rust `aws-sdk-s3` 负责 S3/MinIO 对象访问。
- 借鉴 rclone bisync 的状态记录、增量判断和冲突保护思想，但不把 `rclone.exe` 作为 MKnote 运行时依赖。
- 每个同步对象独立存储，不把三个文件合并成一个容易互相覆盖的大 JSON。
- 默认笔记、Quick Todo、默认 Quick Pocket 保持现有 Markdown 文件格式和本地路径。
- 同步失败只影响云端状态，不影响本地保存和继续编辑。
- 第一版不做自动 Markdown 三方合并；发生冲突时保留两个版本，避免错误覆盖。

## 2. 背景与当前事实

### 2.1 已验证事实

- 当前项目是 Tauri 2 + React 19 + Rust，便签以本地 Markdown 文件为主要数据源。
- 当前 S3 客户端位于 `src-tauri/src/s3_store.rs`，使用 `reqwest` 手写 AWS SigV4。
- 当前 S3 客户端支持对象 `GET`、`PUT` 和连通性测试；没有 ETag、条件写入、对象列表和版本冲突接口。
- 当前短消息同步位于 `src-tauri/src/message_hub.rs`，采用读取远端 JSON、修改后整体 PUT 的方式，属于最后写入覆盖模型。
- 当前默认笔记路径是 `writable_base/default-note.md`。
- 当前 Quick Todo 路径是 `writable_base/inbox/Quick Todo.md`。
- 当前默认 Quick Pocket 路径是 `writable_base/inbox/Quick Pocket.md`。
- Quick Todo 和 Quick Pocket 都已经在 Rust 层实现原子写入，并通过 Tauri 事件通知前端刷新。
- 思源接口位于 `src-tauri/src/siyuan.rs`，当前命令 `siyuan_upload_current_note` 是用户触发的当前便签单向上传，不是多设备双向同步。
- 当前 S3 配置字段是 `s3_endpoint`、`s3_bucket`、`s3_object_key`、`s3_access_key`、`s3_secret_key`，消息中心已经有设置界面和连接测试。

### 2.2 已采纳的产品决策

- 同步对象暂定为三个固定对象：默认笔记、默认 Quick Pocket、Quick Todo。
- 同步应自动运行，不要求用户反复点击“同步”。
- 本地编辑优先，外部网络故障不得阻塞编辑、保存或窗口关闭。
- 尽可能减少风险，优先保护数据不丢失，而不是追求自动合并后的表面无冲突。

## 3. 范围

### 3.1 第一版包含

- S3/MinIO 配置复用现有消息中心配置。
- S3 客户端从手写 SigV4 迁移到 `aws-sdk-s3`，保留现有 Endpoint、Bucket、Access Key、Secret Key 和对象前缀兼容性。
- 自动上传三个固定同步对象。
- 应用启动时自动检查远端版本。
- 应用运行期间定时轮询远端变化，建议默认 20 秒，可配置但不暴露过多复杂选项。
- 保存成功后的防抖上传队列。
- 窗口重新获得焦点时触发一次轻量远端检查。
- 网络失败重试、指数退避、队列合并和应用退出前的有限 flush。
- ETag/版本检查和条件写入。
- 本地干净时安全应用远端更新。
- 本地未保存或本地已修改时保留冲突副本，不覆盖当前编辑内容。
- 同步状态展示：已同步、同步中、离线待重试、发生冲突、配置缺失。
- 默认 Quick Todo 和 Quick Pocket 远端更新后的前端事件刷新。
- 默认笔记远端更新后的编辑器刷新保护。

### 3.2 第二版候选范围

- 同步全部 Quick Pocket。
- 同步 Quick Pocket 注册表 `quick_pockets`。
- Pocket 创建、重命名、删除的远端墓碑记录。
- 颜色标签、收藏、回收站等元数据同步。
- Markdown 三方合并。
- S3 Object Versioning 的恢复界面。

### 3.3 不包含

- 不同步全部普通笔记、资料库文件夹和图片资产。
- 不同步 `config.json`、窗口位置、主题、热键、打开 Tab、AI Token、思源 Token。
- 不替换现有短消息中心对象 `MDnote/messages.json`。
- 不把 `rclone.exe`、Syncthing 或其他常驻外部进程作为运行依赖。
- 不在第一版自动删除远端对象。
- 不在第一版静默采用“远端覆盖本地”或“本地覆盖远端”。
- 不要求 S3 服务端提供实时推送；客户端使用轮询发现远端变化。

## 4. 远端对象协议

### 4.1 对象键

以现有 `s3_object_key` 的目录部分作为同步前缀。例如当前消息对象为 `MDnote/messages.json` 时，使用：

```text
MDnote/sync/default-note.md
MDnote/sync/quick-todo.md
MDnote/sync/quick-pocket-default.md
MDnote/sync/manifest.json
```

现有 `messages.json`、`vault-config.json`、`vault-notes.json` 不迁移、不复用内容格式。

### 4.2 Manifest 结构

`manifest.json` 只记录同步元数据，不承载 Markdown 正文：

```json
{
  "schema_version": 1,
  "generation": 12,
  "items": {
    "default-note": {
      "object_key": "MDnote/sync/default-note.md",
      "revision": 12,
      "content_hash": "sha256:...",
      "etag": "...",
      "updated_at_ms": 1760000000000,
      "device_id": "device-a"
    },
    "quick-todo": {
      "object_key": "MDnote/sync/quick-todo.md",
      "revision": 8,
      "content_hash": "sha256:...",
      "etag": "...",
      "updated_at_ms": 1760000000000,
      "device_id": "device-a"
    }
  }
}
```

正文对象直接保存 UTF-8 Markdown。正文对象不写入额外标记，保证下载后仍可作为普通 Markdown 使用。

### 4.3 本地同步状态

在 `writable_base/.mknote-sync-state.json` 保存每台设备的本地同步状态：

- 固定 `device_id`。
- 每个同步对象的最后远端 revision、ETag、内容哈希。
- 最近一次成功上传/下载时间。
- 待重试队列和冲突状态。
- 不保存 Access Key、Secret Key 或其他密钥。

该状态文件损坏时，程序必须进入“需要重新建立基线”状态，不能直接覆盖本地文件。

## 5. 同步状态机

### 5.1 本地修改

1. 现有保存流程先将 Markdown 原子写入本地。
2. 现有业务事件和 UI 状态照常完成。
3. 同步层收到 `LocalChanged(item_id)`，只保留该对象最新内容。
4. 防抖窗口结束后进入上传队列。
5. 上传前读取当前本地内容并计算 SHA-256，避免上传过期内容。

### 5.2 自动上传

1. 获取远端 manifest 和目标对象当前 ETag。
2. 若远端版本仍等于本地记录的基线，使用条件 PUT 上传。
3. 上传成功后更新 manifest 和本地同步状态。
4. 如果条件 PUT 失败，重新读取远端内容并进入冲突判断。
5. 网络错误进入重试队列，不修改本地文件。

### 5.3 自动下载

1. 启动、定时轮询和窗口重新获得焦点时检查 manifest。
2. 远端 revision/ETag 没有变化时不下载正文。
3. 本地内容哈希等于上次已同步内容时，原子下载并替换本地文件。
4. 替换前写入现有 history 快照，便于恢复。
5. 替换后广播对应的 Quick Todo/Quick Pocket 事件。
6. 默认笔记如果正在编辑，只有在编辑器仍处于 clean 状态时自动替换；dirty 状态进入冲突流程。

### 5.4 冲突处理

冲突定义为：本地基于旧远端版本发生了修改，同时远端也已经产生了新版本。

处理顺序：

1. 保留当前本地内容，不直接覆盖。
2. 将远端内容写入 `.mknote-sync-conflicts/<item>-<timestamp>-<device>.md`。
3. 记录冲突元数据：本地哈希、远端哈希、基线 revision、发现时间。
4. 状态栏显示“存在同步冲突”。
5. 后续提供“保留本地”“采用远端”“另存两份”三个明确动作。
6. 用户未选择前，后台不得继续用任一版本覆盖另一版本。

第一版不自动合并 Quick Todo 或 Quick Pocket，避免破坏 ID、父子关系、分组和 Markdown 注释结构。

## 6. 执行阶段

### Phase 0：协议冻结与数据保护基线

- 目标：在写入同步代码前冻结对象范围、键名、冲突规则和备份边界。
- 输入：`src-tauri/src/s3_store.rs`、`src-tauri/src/message_hub.rs`、`src-tauri/src/notes.rs`、`src-tauri/src/quick_todo.rs`、`src-tauri/src/quick_pocket.rs`。
- 动作：
  1. 确认三个固定对象不包含普通笔记和图片资产。
  2. 确认同步前缀不覆盖 `messages.json` 和 Vault 对象。
  3. 增加同步功能开关，默认关闭，避免升级后自动覆盖已有数据。
  4. 首次启用时要求选择“以本地建立远端基线”或“以远端建立本地基线”；之后进入全自动模式。
  5. 为本地三个文件生成一次只读快照或使用现有 history 机制记录基线。
- 输出：协议说明、对象键常量、初始配置字段设计、首次启用流程设计。
- 验收：
  - 三个对象的本地路径、远端键和不包含范围明确。
  - 首次启用不会无提示覆盖本地或远端内容。
  - 现有短消息和 Vault 对象路径保持不变。
- 停止条件：发现用户需要同步全部普通笔记、图片或配置时，暂停并重新划分协议，不能继续沿用本计划的固定对象模型。

### Phase 1：S3 访问层升级

- 目标：提供可验证的 S3 对象读取、ETag、条件写入和重试能力。
- 输入：`src-tauri/src/s3_store.rs`、`src-tauri/Cargo.toml`、现有 S3 配置字段。
- 动作：
  1. 引入 `aws-sdk-s3`，配置自定义 Endpoint、区域 `us-east-1` 和 S3/MinIO 兼容访问。
  2. 封装 `get_object`，返回正文、ETag 和响应版本信息。
  3. 封装 `put_object` 与基于 ETag 的条件写入。
  4. 增加对象不存在、认证失败、超时、连接失败和条件冲突的分类错误。
  5. 增加指数退避，但设置最大重试次数和总超时。
  6. 保留现有消息中心和 Vault 的调用兼容层，避免本阶段改变业务行为。
- 输出：可复用的 S3 对象访问模块和单元测试。
- 验收：
  - MinIO/S3 兼容 Endpoint 可完成 PUT、GET、ETag 读取和条件冲突测试。
  - 错误类型可以区分网络失败与远端版本冲突。
  - S3 密钥不出现在日志和错误文本中。
  - 现有消息中心和 Vault 测试不回归。
- 停止条件：当前 S3 服务不支持 ETag 或条件写入时，不直接放弃保护机制；改为使用 manifest generation 校验，并明确该后端只能提供较弱的冲突保护。

### Phase 2：同步核心与本地状态

- 目标：实现不依赖 UI 点击的同步引擎，但暂不接入所有现有编辑入口。
- 输入：Phase 1 S3 访问层、三个本地文件路径、现有 history/原子写入工具。
- 动作：
  1. 新增 `src-tauri/src/sync.rs`，定义 `SyncItemId`、`SyncManifest`、`SyncItemState`、`SyncStatus` 和 `SyncConflict`。
  2. 实现 manifest 解析、schema 校验、内容哈希和本地状态持久化。
  3. 实现启动同步、单项上传、单项下载、远端检查和冲突副本写入。
  4. 实现单进程同步锁，避免多个后台任务同时覆盖同一对象。
  5. 实现内存队列去重：同一对象连续修改只上传最新内容。
  6. 实现重试队列和应用退出前的短时 flush；超过时间立即结束，不阻塞退出。
  7. 为本地下载增加原子替换和 history 快照。
- 输出：独立同步核心、状态文件、冲突文件格式和 Rust 单元测试。
- 验收：
  - 本地修改能够进入队列并自动上传。
  - 远端新版本能够自动下载到 clean 本地文件。
  - dirty 本地文件不会被远端版本覆盖。
  - ETag 不匹配时能够生成冲突副本。
  - 网络断开、恢复、重复触发不会造成数据丢失或重复写入。
- 停止条件：出现一次无法恢复的本地正文丢失、状态文件覆盖有效数据或冲突版本未保留，立即停止接入 UI，先修复核心测试。

### Phase 3：接入现有保存和变更事件

- 目标：让同步行为自动跟随现有业务保存，不改变用户的本地编辑体验。
- 输入：`src-tauri/src/lib.rs`、`src-tauri/src/notes.rs`、`src-tauri/src/quick_todo.rs`、`src-tauri/src/quick_pocket.rs`、前端事件监听位置。
- 动作：
  1. 在默认笔记成功写入后发送同步变更事件。
  2. 在 Quick Todo 原子写入成功后加入同步队列。
  3. 在默认 Quick Pocket 原子写入成功后加入同步队列。
  4. 为启动、定时器、窗口 focus 和网络恢复接入远端检查。
  5. 远端下载后复用 `mknote:quick-todo-changed` 和 `mknote:quick-pocket-changed:default` 刷新 UI。
  6. 默认笔记下载前检查当前编辑状态，clean 才自动替换，dirty 则进入冲突状态。
  7. 将同步状态通过 Tauri command/event 提供给状态栏或设置面板。
- 输出：自动同步运行时、同步状态 UI、冲突提示 UI。
- 验收：
  - 用户只编辑和保存，不需要点击同步按钮。
  - Quick Todo、Quick Pocket 的远端变化能刷新当前窗口。
  - 默认笔记被远端更新时不会覆盖未保存输入。
  - 同步失败不会让本地保存显示为失败。
  - 关闭 Quick 窗口和隐藏主窗口前仍能保存本地内容。
- 停止条件：发现同步网络调用阻塞编辑线程、阻塞窗口关闭或导致 UI 事件循环卡顿，回退为后台线程并保留本地优先行为。

### Phase 4：双设备与异常场景验收

- 目标：证明自动同步不是“单设备上传成功”而是真正可恢复的多设备同步。
- 输入：两个独立数据目录、同一 S3/MinIO Bucket、自动化测试脚本和现有测试命令。
- 动作：
  1. 设备 A 创建和修改三个同步对象，验证设备 B 自动拉取。
  2. 设备 B 离线编辑，设备 A 在线编辑，恢复网络后制造 ETag 冲突。
  3. 验证冲突副本、原始本地版本和远端版本都可读取。
  4. 测试应用崩溃、上传中断、重复启动、S3 返回 404/403/5xx、凭据失效和 Endpoint 不可达。
  5. 测试 Quick Todo 父子项、完成状态、提醒和链接的完整 Markdown 保留。
  6. 测试 Quick Pocket 标签、内文、分组、组名和顺序的完整 Markdown 保留。
  7. 验证消息中心和 Vault 仍使用原有对象且内容不互相污染。
- 输出：双设备验收记录、失败场景记录、可恢复性结论。
- 验收：
  - 自动上传、自动下载、断网重试、冲突保留全部通过。
  - 没有未解释的覆盖、删除或静默丢失。
  - 目标测试、构建、打包和真实交互 smoke 分开记录。
- 停止条件：任一数据丢失场景无法通过冲突副本或 history 恢复，不能发布自动同步功能。

### Phase 5：逐步启用与发布

- 目标：在可回滚的前提下向用户启用自动同步。
- 输入：Phase 4 验收包、配置迁移方案、发布构建流程。
- 动作：
  1. 新增同步设置页，展示配置状态、最近同步时间、待重试数量和冲突数量。
  2. 首次启用提供一次性基线选择，不把它设计成日常手动同步。
  3. 记录同步协议版本，未来升级时拒绝解析未知高版本 manifest。
  4. 保留禁用同步开关和本地数据导出路径。
  5. 使用 `npm.cmd run build`、目标测试、`npm.cmd run build:green` 和双设备 smoke 验证。
  6. 发布说明明确：第一版同步范围、冲突处理方式、S3 权限要求和恢复方式。
- 输出：发布版本、同步设置文案、验收包和回滚说明。
- 验收：
  - 新配置缺省时不改变当前本地行为。
  - 关闭同步后不再访问同步对象，但保留本地内容。
  - 绿色包中不包含测试数据、密钥、临时状态或冲突样例。
  - 发生严重问题时可以关闭同步并继续使用本地模式。
- 停止条件：无法提供明确的禁用、恢复和本地导出路径时，不发布默认自动同步。

## 7. 预计代码边界

### 新增或主要修改

- `src-tauri/src/sync.rs`：同步状态机、manifest、队列、冲突处理。
- `src-tauri/src/s3_store.rs`：官方 SDK 访问层或兼容适配层。
- `src-tauri/src/lib.rs`：同步 command、event、配置字段注册。
- `src-tauri/src/notes.rs`：默认笔记成功写入后的同步事件。
- `src-tauri/src/quick_todo.rs`：Quick Todo 成功写入后的同步通知接入。
- `src-tauri/src/quick_pocket.rs`：默认 Pocket 成功写入后的同步通知接入。
- `src/types.ts`：同步配置、状态和冲突类型。
- `src/components/CompactView.tsx` 或现有设置组件：同步状态与首次启用入口。
- `src-tauri/Cargo.toml`：S3 SDK 和必要的运行时依赖。

### 明确不应直接修改的对象

- `MDnote/messages.json`：短消息中心对象。
- `MDnote/vault-config.json`、`MDnote/vault-notes.json`：云端保险库对象。
- 现有 Quick Todo / Quick Pocket Markdown 标记格式，除非发现协议无法保留现有内容。

## 8. 测试与验收矩阵

| 层级 | 重点 | 通过条件 |

## 9. 风险与安全边界

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 两台设备同时 PUT | 后写入覆盖先写入 | ETag 条件写入；失败转冲突副本 |
| S3 不支持条件写入 | 并发保护变弱 | manifest generation 校验；发布前明确后端兼容矩阵 |
| 远端更新覆盖正在编辑内容 | 用户输入丢失 | dirty 状态禁止自动替换 |
| 网络失败阻塞编辑 | 应用卡顿或无法保存 | 本地先写；同步在后台线程；有限重试 |
| manifest 损坏 | 无法判断版本 | 校验 schema；保留旧状态；进入重新建立基线状态 |
| Quick Todo/ Pocket Markdown 被错误重写 | 标签、父子项或分组损坏 | 正文按原文件传输；不做第一版自动合并 |
| S3 凭据泄露 | 远端数据被读取或修改 | 不写日志；限制 Bucket 前缀权限；优先 HTTPS；后续评估 Windows Credential Manager |
| 误同步普通笔记或私密数据 | 隐私泄露 | 固定对象白名单；不从 Bucket 列表推断同步范围 |
| 应用退出时上传未完成 | 最近修改未上传 | 状态持久化、后台重试；退出 flush 设硬时限，不阻塞退出 |

未经用户明确批准，不得：

- 删除或覆盖现有远端 `messages.json`、Vault 对象或普通笔记对象。
- 自动同步全部普通笔记、图片、配置或密钥。
- 在首次启用时无提示选择本地或远端作为基线。
- 在冲突情况下静默采用本地或远端版本。
- 将 `rclone.exe`、Syncthing 或其他外部常驻进程加入发布包。
- 仅凭 `BUILD SUCCESSFUL` 宣布同步功能完成；必须完成双设备真实交互验证。

## 10. 回滚与恢复方案

- 功能开关关闭后，MKnote 回到纯本地模式，保留本地三个 Markdown 文件。
- 删除或禁用同步配置不会删除本地文件和远端对象。
- 每次远端下载前写入 history 快照；自动替换错误时从 history 恢复。
- 冲突版本写入独立目录，不覆盖原文件。
- 同步状态文件损坏时删除的是状态文件副本，不删除正文；程序要求重新建立基线。
- S3 SDK 迁移失败时保留旧访问层兼容分支，先回退客户端实现，不回退用户数据。
- 发布前保存现有配置和三个本地文件的校验哈希，作为升级验收基线。

## 11. 完成定义

只有同时满足以下条件，才可称为“自动同步完成”：

- 三个目标对象可在两个独立设备实例间自动上传和下载。
- 用户日常编辑不需要点击同步按钮。
- 断网、重试、重启后能恢复同步队列。
- 本地 dirty 内容不会被远端静默覆盖。
- ETag 或等价版本检测能阻止并发覆盖；冲突内容可完整恢复。
- Quick Todo 的父子项、提醒、链接和完成状态保持正确。
- Quick Pocket 的标签、正文、分组和顺序保持正确。
- 现有消息中心、Vault、思源上传和普通本地笔记行为不回归。
- 目标测试、构建、绿色打包和双设备真实 smoke 分别有记录。
- 同步可关闭，且关闭后仍可安全使用本地模式。
