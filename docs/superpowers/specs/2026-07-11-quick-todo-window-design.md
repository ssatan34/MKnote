# MKnote v3.4 Quick Todo 面板与独立窗口设计

> 日期：2026-07-11
>
> 状态：待用户书面审查
>
> 范围：Quick Todo；不包含 Quick Pocket 与桌面顶部吸附

## 1. 决策摘要

Quick Todo 不再采用“每次输入都创建一篇独立 Inbox 笔记”的模型，而是使用一个 Markdown 文件：

```text
{base}/inbox/Quick Todo.md
```

产品分两阶段交付，但不实现两套 Todo：

1. 先构建共享的 `QuickTodoPanel + store`，在程序内完成数据与交互验收。
2. 再把同一组件挂入已验证的独立 Tauri 窗口壳。

在完整面板开发前，先做一个最小独立窗口空壳探针，尽早验证 Windows 焦点、截图、点击和几何风险。空壳探针通过不代表独立窗口功能已交付；完整独立窗口仍是第二阶段验收项。

## 2. 目标

- 程序内提供与参考图一致的紧凑 Todo 列表面板。
- 支持快速添加、勾选完成、删除、自动“今天”标记和未完成计数。
- Markdown 在普通文本编辑器中仍然可读。
- 程序内面板与独立窗口共享同一组件、状态接口和数据文件。
- 最终独立窗口可靠可点，不抢前台，不破坏截图、置顶、Capsule 或 Popout。
- 各阶段分别可构建、可测试、可人工验收、可回滚。

## 3. 非目标

- 本规格不实现 Quick Pocket。
- 不在本轮实现桌面顶部吸附、悬停展开、点击穿透或 YASB 避让。
- 不把 Quick Todo 接入 Capsule/Popout 状态机。
- 不恢复旧的专用“待办事项.md”双列任务系统。
- 不自动迁移此前测试产生的时间戳 Inbox 笔记；这些笔记保持原状。
- 不引入搜索、优先级、提醒、子任务或复杂日期系统。

## 4. 参考界面与交互

程序内面板以用户参考图中的 Quick Todo 为目标，但使用 MKnote 的 `DESIGN.md` token：

- 标题行：Todo 图标、`Quick Todo`、未来独立窗口使用的置顶按钮、关闭按钮。
- 输入行：单行输入框和 icon-only 提交按钮。
- 列表行：未完成/已完成圆形状态、任务文字、自动“今天”标记、icon-only 删除按钮。
- 底部：`N 条待处理`；可折叠列表，但折叠后仍保留输入能力。
- Enter 添加；Esc 关闭当前面板或返回触发按钮；空白不可提交。
- 添加成功后输入框保持可继续输入，不切换主窗口当前笔记，不新增主窗口 Tab。
- 完成项保留在原位置并显示弱化/删除线；不自动归档、不自动重排，未完成计数不包含完成项。
- “今天”根据 `createdAt` 与当前本地日期自动显示，不提供手动日期或提醒编辑。
- 数据操作失败时保留输入或原列表状态，并显示可理解的错误。

程序内入口继续放在主标题栏。面板是非模态 popover，不使用 backdrop，不阻塞编辑器。

## 5. 数据格式

文件使用普通 Markdown checklist；每条任务在行尾携带最小 HTML 注释元数据：

```markdown
# Quick Todo

- [ ] 规划周会提纲 <!-- quick-todo:id=qt_01 createdAt=2026-07-11T00:00:00Z -->
- [x] 整理 Hermes 相关资料 <!-- quick-todo:id=qt_02 createdAt=2026-07-10T10:00:00Z completedAt=2026-07-11T01:00:00Z -->
```

约束：

- `id`：稳定唯一标识，不依赖文本内容或列表索引。
- `createdAt`：创建时间，ISO 8601 UTC。
- `completedAt`：仅完成项存在；取消完成时移除。
- Markdown 行顺序就是界面顺序。
- 未识别的普通 Markdown 内容必须原样保留；解析器不得静默删除用户内容。
- 缺失或损坏的元数据不得导致整个文件不可读；无法管理的行按普通 Markdown 保留。

## 6. 架构边界

### 6.1 共享视图

`QuickTodoPanel` 只接收状态和动作，不直接调用 Tauri：

```ts
interface QuickTodoPanelProps {
  items: QuickTodoItem[];
  loading: boolean;
  error: string | null;
  onAdd(text: string): Promise<void>;
  onToggle(id: string): Promise<void>;
  onDelete(id: string): Promise<void>;
  onClose(): void;
  headerActions?: React.ReactNode;
}
```

程序内 popover 与独立窗口都渲染该组件。窗口专属的置顶按钮由窗口壳注入，不能写死在共享业务组件里。

### 6.2 状态与服务

前端 `quickTodoService` 只负责调用后端命令和订阅变化事件。Rust 是文件读写真相源：

- `quick_todo_list`
- `quick_todo_add`
- `quick_todo_toggle`
- `quick_todo_delete`

每次成功写入后广播 `mknote:quick-todo-changed`，主窗口和独立窗口收到后重新读取列表。前端不自行合并两个窗口的并发修改。

### 6.3 文件一致性

- Rust 侧对 Quick Todo 写操作使用进程内互斥锁。
- 每次操作执行“读取最新文件 → 纯函数变换 → 原子写入”。
- 不允许“加载一次后长期持有旧快照再覆盖”的写法。
- 写入失败不得广播成功事件。

## 7. 分阶段实施与验收门

### 阶段 A：窗口行为前置修复与空壳探针

先修复已确认的截图回归：`fullscreen_watcher` 在截图全屏结束后不得调用会 `SetForegroundWindow` 的强显示路径，应无激活地被动恢复窗口。

随后创建最小 Quick Todo 独立窗口空壳，只包含标题和关闭按钮，不接入 Todo 数据。

人工验收：

- 主窗口、空壳窗口均不因截图结束而抢前台。
- 打开空壳是用户显式动作；打开后可以正常点击。
- 关闭只隐藏或关闭空壳，不影响主窗口与 Capsule/Popout。
- 多次打开只存在一个 Quick Todo 窗口。
- 关闭按钮只隐藏窗口并保存逻辑坐标/尺寸，应用退出才销毁窗口。
- 重开优先恢复上次逻辑坐标/尺寸并夹紧到当前可用显示器；没有历史几何时，居中于主窗口所在显示器。
- `always_on_top=false` 时不置顶；用户显式开启后才置顶。

任一项失败则停止，不继续构建完整独立窗口。

### 阶段 B：程序内 Quick Todo 面板

实现 Markdown 模型、Rust 命令、共享 `QuickTodoPanel` 和程序内 popover。

人工验收：

- 添加不会创建时间戳 Inbox 笔记，不切换当前编辑笔记。
- 勾选、取消完成、删除、自动“今天”标记和未完成计数正确。
- 重启后数据与顺序保留。
- 直接编辑 `Quick Todo.md` 后重新打开面板可正确读取。
- 输入、长文本、空白和错误状态显示正常。
- Capsule、Popout、截图和主窗口置顶无回归。

阶段 B 通过后才允许进入阶段 C。

### 阶段 C：独立 Quick Todo 窗口

把阶段 B 的同一 `QuickTodoPanel` 挂入阶段 A 已验证的窗口壳。主窗口入口改为“打开/聚焦 Quick Todo 窗口”，但程序内面板可作为开发回退路径保留到独立窗口验收完成。

人工验收：

- 独立窗口与程序内面板显示同一数据，无需刷新应用。
- 独立窗口输入、勾选、删除、自动“今天”标记全部可用。
- 不抢占其他应用焦点；截图完成后不置前。
- 置顶仅由用户显式控制并持久化。
- 关闭、重开、重启、显示器切换和 DPI 缩放行为稳定。
- 主窗口和独立窗口同时操作不会丢数据或覆盖新内容。

### 阶段 D：可选桌面吸附

只有阶段 C 验收后，才另开分支处理顶部吸附、悬停展开、点击穿透、边界、YASB 避让等桌面功能。

## 8. 错误处理

- 文件不存在：首次读取时创建带 `# Quick Todo` 标题的文件。
- 文件不可写：面板显示错误，保留用户输入，不伪造成功。
- 单条元数据损坏：保留原文并跳过该条的管理操作。
- 并发操作：后端锁内重新读取最新文件；操作目标不存在时返回明确错误并触发刷新。
- 独立窗口初始化失败：主窗口显示错误，程序内面板仍可使用；不得启动半透明或不可点击的残留窗口。

## 9. 测试策略

### 纯函数测试

- 解析 checklist、完成状态和元数据。
- 序列化后保持普通 Markdown 与未知内容。
- 添加、切换、删除只修改目标项；“今天”标记按本地日期派生。
- 损坏元数据与重复 ID 的降级行为。

### Rust 测试

- 文件首次创建。
- 原子写入与写入失败。
- 连续操作基于最新文件，不覆盖前一次结果。
- 变化事件只在成功写入后发出。
- 全屏避让恢复决策必须选择无激活路径。

### 前端测试

- Enter 添加、空白禁用、提交失败保留输入。
- 勾选、删除、自动“今天”标记与计数。
- 共享面板不依赖主窗口 DOM 或 Tauri window label。

### Windows 人工/E2E

- 截图遮罩停留超过 fullscreen watcher 轮询周期后完成/取消。
- 普通窗口与置顶窗口两种配置。
- 单屏、多屏、不同 DPI。
- 显式打开应聚焦；后台被动恢复不得聚焦。

## 10. 当前代码迁移

- 保留当前标题栏 Quick Todo icon 入口与基础输入交互样式作为起点。
- 移除当前 `quick_capture_create → 每项独立 Inbox note → 自动打开 Tab` 的 Quick Todo 接线。
- 通用 `quick_capture_create` 命令继续服务原有剪贴板/快速捕获场景，不删除、不改变语义。
- 新 Quick Todo 使用独立命令与 `Quick Todo.md`，避免影响现有 Inbox 捕获。
- 在阶段 B 验收前，不提交“完整 Quick Todo 已完成”的版本节点。

## 11. 成功标准

最终成功不是“窗口能出现”，而是同时满足：

1. Todo 数据稳定、Markdown 可读、操作不丢失。
2. 程序内与独立窗口使用同一实现。
3. 独立窗口可点击、可关闭、可恢复、可选置顶。
4. 不抢焦点，不在截图结束后置前。
5. 不破坏主窗口、Capsule、Popout 与现有快速捕获。
