# 密码输入框眼睛图标位移问题复盘

- 日期：2026-07-15
- 范围：思源、短消息 S3、AI 配置页的密码输入框眼睛按钮
- 状态：部分完成

## 一句话结论

问题表面上像是眼睛 SVG 切换时发生了位移，实际应优先检查密码输入框内部的布局参照链。最终方案是让 input 与眼睛按钮共用一个 CSS Grid 单元格，由 Grid 负责垂直居中，不再使用 top: 50% + translateY(-50%)。

## 目标与范围

- 目标：点击眼睛显示密码，5 秒后恢复打码；眼睛按钮在两种状态下保持位置不变。
- 包含：AI Token、思源 API Token、S3 Secret Key。
- 不包含：其他设置输入框、密码存储逻辑、按钮业务逻辑。

## 已完成

- 新增共用组件：src/components/PasswordInput.tsx。
- 三个设置页统一使用共用密码输入组件。
- 眼睛主体固定使用同一个 SVG，只切换斜杠的透明度，避免切换两个不同 SVG 的视觉重心差异。
- 密码输入包装器改为 CSS Grid：
  - input：grid-area: 1 / 1
  - 眼睛按钮：grid-area: 1 / 1
  - 按钮通过 align-self: center 垂直居中
- 移除了按钮的百分比绝对定位和 translateY(-50%)。

## 关键决策

| 决策 | 原因 | 影响 |
|---|---|---|
| 不再切换 eye / eye-off 两个完整 SVG | 两个图形的视觉重心可能不同，容易产生“跳动”错觉 | 保持眼睛主体位置稳定 |
| 不使用 top: 50% 定位按钮 | 当前结构包含 label → span → input，行盒/基线会影响参照高度 | 由 Grid 直接完成输入框内垂直居中 |
| 保留 line-height: 0 与 input { display: block } | 消除 input 的 inline 基线空隙 | 避免包装器高度被行盒撑出额外空间 |

## 下次排查顺序

1. 先看按钮整体是否偏移；如果按钮背景也偏移，优先查父容器布局和定位参照，不要先改 SVG。
2. 检查按钮的 position、top/right、transform 以及最近的 position: relative 祖先。
3. 检查 input 是否为 inline/inline-block，是否存在 baseline 空隙；优先设置包装器 line-height: 0、input display: block。
4. 如果按钮位置稳定但图形仍跳动，再检查 SVG 的 viewBox、path 边界和视觉重心。
5. 对输入框内操作按钮，优先采用“同一 Grid 单元格叠放”而不是百分比绝对定位。
