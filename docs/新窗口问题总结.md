便签弹出窗口问题总结

  问题链与根因

  这次修复的是一个弹出窗口功能从无到有的完整实现，遇到的问题呈现出明显的层级依赖关系：

1. 死锁导致完全白屏（最底层）
   现象：右键 Tab →「在新窗口中打开」后，弹出纯白窗口，程序完全卡死，终端停在 [detach] building popout window。
   根因：open_note_popout 是同步 #[tauri::command]，在 Tauri 2 中同步命令运行在主线程上。而
   WebviewWindowBuilder::build() 创建窗口时需要主线程去泵消息循环才能完成窗口初始化 → 主线程正卡在 build()
   里等它返回 → 自己等自己 → 死锁。
   解决：改成 pub async fn。async 命令运行在独立工作线程，build()
   会把窗口创建派发给空闲的主线程并等待，主线程不被占住，死锁解除。

  ---

2. 主窗口事件误作用于 popout，导致抖动卡死
   现象：窗口能打开了，但无法编辑（点进编辑框瞬间焦点被夺走），关闭时主窗口疯狂抖动闪烁，整个应用卡死。
   根因：lib.rs 的全局 on_window_event 对每一个窗口的事件都触发，但不管事件来自谁，它总是拿到主窗口去处理：
- popout 获得焦点 → 回调对主窗口执行 force_present + set_always_on_top → 主窗口被强行置前抢走焦点 →
  两窗口焦点无限来回弹 → 抖动、卡死

- popout 点关闭 → 回调对主窗口执行 prevent_close + hide_main_window → 主窗口被隐藏，popout 自己关不掉
  解决：在全局回调入口加 if window.label() != WINDOW_LABEL { return }，只处理主窗口自己的事件。popout 的事件由
  detach.rs 里 popout 自己的 on_window_event 处理。

  ---

3. 关闭按钮无法关闭窗口
   现象：点关闭按钮，窗口不关，CPU 持续占用。
   根因：无限递归。handleClose → invoke(close_note_popout) → Rust w.close() → 触发 CloseRequested 事件 →
   onCloseRequested 里 preventDefault() + 再调 handleClose → 又 close() → 又 CloseRequested → 死循环。
   解决：
- Rust 侧：close() 改成 destroy()。destroy() 强制销毁窗口、完全不发
  CloseRequested，从根上消除拦截和循环的可能。
- 前端侧：加 closingRef 守卫防重入；守卫激活后 onCloseRequested 放行不再 preventDefault；命令失败兜底
  destroy()。
- 补上 core:window:allow-destroy 权限。

  ---

4. 编辑区高度只有 3 行
   现象：popout 窗口打开后，编辑区只显示约 3 行文本，需要滚动条才能看下文。
   根因：.popout-editor 是 overflow:hidden 但没有 display:flex，所以里面 textarea.editor 的 flex:1 失效 →
   textarea 退回内容高度（约 3 行）。
   解决：给 .popout-editor 加 display:flex; flex-direction:column，textarea 就能撑满。

  ---

5. popout 的修改不写回主窗口（最隐蔽）
   现象：popout 里改内容、关闭，磁盘确实保存了（重开 popout
   内容还在），但主窗口切回该笔记时显示的是弹出前的旧内容。
   根因链（这是最复杂的一个，根因其实是问题 6）：

6. CompactView.tsx 过滤已弹出 Tab 时用的 key 是 `${zone}:${name}`（冒号），但 poppedOutNotes 里存的是 tabKey()
   生成的 zone\u0000name（空字符分隔）→ key 永不匹配 → Tab 从未被隐藏

7. Tab 没隐藏 → 主窗口一直挂着该笔记的活跃编辑器，contentRef 持有弹出前的旧内容

8. popout 改磁盘 → 关闭 → 主窗口下次自动保存/blur 时，用旧的 contentRef 把 popout 的修改覆盖掉了
   解决：
- 统一 key：CompactView 的过滤改成 tabKey(t.zone, t.name)，与 poppedOutNotes 一致 → Tab 真正隐藏 →
  主窗口切走、不再持有活跃编辑器 → 覆盖消失。
- 加两道保险：
  - 弹出时 tabSessions.remove(zone, name) 清缓存
  - popout-closed 归还 Tab 后，若该笔记仍是主窗口的活跃笔记（弹出时它是唯一 Tab、无法切走），从磁盘重载编辑器

  ---

6. Tab 打开 popout 后未隐藏
   现象：设计意图是打开 popout 后主窗口该 Tab 消失，关闭才归还。但 Tab 一直可见。
   根因：同问题 5 的 key 不匹配（`${zone}:${name}` vs tabKey()）。
   解决：同问题 5 的 key 统一修复。

  ---

7. popout 标题栏 icon 与设计不符
   现象：popout 左上角是静态 logo，用户期望与主窗口标题栏一样是可点击的颜色标签。
   根因：设计遗漏，初始实现用的是 IconLogoPlaceholder。
   解决：
- 替换成 ColorTagSwatch + ColorTagPicker
- 加载笔记颜色 + 自定义标签（list_notes / list_custom_tags）
- 点击弹出颜色选择器，走 set_note_color 修改
- 加 CSS 和点击外部/Esc 关闭逻辑

  ---

  关键教训

1. Tauri 2 同步命令 + 窗口创建 = 死锁
   WebviewWindowBuilder::build() 必须在 async 命令里调用，否则主线程自我等待。
2. 全局事件回调必须区分窗口
   .on_window_event() 对所有窗口触发，必须用 window.label() 判断身份，否则 popout 的事件会误作用到主窗口。
3. 字符串 key 的隐形陷阱
   `${zone}:${name}` 和 tabKey(zone, name) 看似"都是拼接"，但一个用冒号、一个用空字符，永不匹配。这种 bug
   无法从单处源码看出，只能通过数据流对照发现。统一用 tabKey() 工具函数避免分歧。
4. close() vs destroy()
   close() 发出可拦截的 CloseRequested 事件，容易形成递归；destroy() 强制销毁，不可拦截，适合程序式关闭。
5. CSS flex 容器的隐性依赖
   子元素的 flex:1 只在父容器是 display:flex 时生效，否则退回默认高度。
6. 调试白屏问题的正确姿势
   - dev 下自动 open_devtools()
   - Rust 侧打 eprintln! 确认执行到哪
   - 前端加防白屏兜底（任何错误都画到窗口上）
   - 看终端输出确认 Rust 是否重编
