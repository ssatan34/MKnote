## 一句话结论

新增一个主题不能只修改前端主题列表。主题名称还必须同步加入 Rust 后端的 `validate_theme_style` 白名单，否则界面可以显示该主题，但点击后保存配置会被后端拒绝。

## 为什么必须同步后端白名单

主题设置由前端发起保存，但配置最终由 Tauri/Rust 命令处理。`set_theme_styles` 会分别校验以下三个字段：

- `light_theme`
- `dark_theme`
- `accent_skin`

三个字段都会调用 `validate_theme_style`。因此，主题必须同时满足：

1. 前端类型和选择器允许该值；
2. 主题 token 和预览数据能够根据该值渲染；
3. Rust 白名单允许该值持久化。

如果只完成前两步，典型表现就是主题卡片已经出现在设置页，但点击后弹出“主题样式必须是……”的错误提示，配置不会成功保存。

## 新增主题同步清单

以后每新增一个主题，至少检查以下位置：

| 顺序 | 位置 | 需要同步的内容 | 必需性 |
| --- | --- | --- | --- |
| 1 | `src/types.ts` | `ThemeStyle` 联合类型 | 必须 |
| 2 | `src/constants/themeAccents.ts` | 浅色和深色模式的强调色映射 | 必须 |
| 3 | `src/components/compact/UnifiedSettingsPanel.tsx` | `THEME_STYLES` 主题列表和 `THEME_PREVIEW_COLORS` 预览色 | 必须 |
| 4 | `src/styles/tokens.css` | 主题的浅色/深色 CSS token、字体和状态色 | 必须 |
| 5 | `src/styles/accent-selection-ui.css` | 主题选择器、激活状态和强调色适配 | 必须 |
| 6 | `src-tauri/src/lib.rs` | `validate_theme_style` 白名单及错误提示 | 必须，最容易遗漏 |
| 7 | `DESIGN.md` | 设计契约中的主题列表和调色板说明 | 建议同步 |
| 8 | `docs/MKnote-UI-v2.md` | UI 主题列表和浅色合成规则 | 建议同步 |

`src/components/ThemeSelect.tsx` 仍保留旧的主题选择组件实现。虽然当前设置页主要使用紧凑设置面板中的选择器，但维护主题时应一并检查该文件，避免备用入口出现主题列表不一致。

## 后续维护规则

主题新增的完成标准不是“主题卡片能显示”，而是“主题能显示、能套用、能保存、重启后仍能恢复”。提交主题相关改动前，必须把 Rust 白名单作为同步项检查；如果未来将主题来源改为动态注册，也要保留后端输入校验，不能只依赖前端隐藏选项。

当前仍未建立专门的 `validate_theme_style` 自动化单元测试。后续可为白名单补充测试，至少覆盖全部合法主题和一个非法主题，以避免再次出现前端已注册、后端未放行的问题。
