# Plan：胶囊模式

> 状态：草稿
> 优先级：高（核心交互升级，分两阶段实现）

---

## 背景

> 历史方案说明：本文最初以 `FloaterView` 为胶囊原型。该组件已移除，当前实现和验收以 `CapsuleView` 为准；文中的旧组件引用仅保留作设计演进记录。

MKnote 目前有一个雏形的迷你浮条（`FloaterView`，约 52×52px 的 Logo 圆形）。它只有"拖动/点击恢复"两个行为，没有任何内容展示，且窗口尺寸切换依赖 `windowLayout.ts` 的手动计算。

PaperTodo 的胶囊模式提供了成熟的参考：便签折叠为细条胶囊，贴边后自动滑入屏幕边缘，鼠标悬浮时滑出。

MKnote 的场景和 PaperTodo 不同（单窗口多 Tab，而非多窗口），因此胶囊模式需要适配：

- **胶囊态** = 当前窗口收缩为一个细横条/竖条，展示所有 Tab 的标题（或颜色标签），可快速切换和展开
- 最终形态可支持**贴边吸附**，鼠标离开后自动滑入屏幕边缘

计划分两个阶段：

| 阶段 | 内容 | 难度 |
|------|------|------|
| Phase 1 | UI 折叠：窗口收缩为胶囊条，显示 Tab 列表，可切换/展开 | 中 |
| Phase 2 | 贴边吸附：离开鼠标后滑到屏幕边缘，悬浮时滑出 | 高 |

---

## Phase 1：UI 折叠胶囊

### 目标

- 点击顶栏某个按钮（或双击标题栏空白区），当前窗口收缩为「胶囊条」
- 胶囊条显示：所有 Tab 的标题（截断 + tooltip）、当前活跃 Tab 高亮
- 点击任意 Tab 标题 → 展开到对应 Tab
- 胶囊条可拖动位置
- 收缩/展开有简单过渡动画

### 胶囊条视觉规格

```
┌─────────────────────────────────────────────────┐
│ ⊞  [笔记标题A]  [笔记标题B●]  [笔记标题C]  [+] │  ← 约 40px 高
└─────────────────────────────────────────────────┘
```

- 高度：40px（可拖动整条窗口）
- 宽度：跟随 Tab 数量自适应，最小 280px，最大 600px
- `●` 标记当前活跃 Tab
- `+` 按钮快速新建笔记
- 超出宽度时 Tab 横向滚动

### 方案设计

#### 前端新组件 `CapsuleView.tsx`

```tsx
interface CapsuleViewProps {
  tabs: OpenTabRef[];
  activeZone: string;
  activeName: string;
  onSelectTab: (zone: string, name: string) => void;
  onNewNote: () => void;
  onExpand: () => void;
}
```

渲染一个横向细条，包含：
- 左侧拖拽区（触发 `startDragging()`）
- Tab 列表（横向滚动）
- 右侧新建 + 展开按钮

#### 窗口尺寸切换（Rust `system.rs`）

新增两个 Tauri 命令：

```rust
// 折叠为胶囊：保存当前几何，切换为胶囊尺寸
#[tauri::command]
pub fn enter_capsule_mode(app: AppHandle) -> Result<AppConfig, String>

// 展开：恢复保存的几何
#[tauri::command]
pub fn leave_capsule_mode(app: AppHandle) -> Result<AppConfig, String>
```

胶囊尺寸常量：
```rust
const CAPSULE_HEIGHT: f64 = 44.0;
const CAPSULE_MIN_WIDTH: f64 = 280.0;
const CAPSULE_MAX_WIDTH: f64 = 600.0;
```

`enter_capsule_mode` 流程：
1. 调用 `save_window_geometry`（保存当前尺寸）
2. 计算胶囊宽度（根据 Tab 数量估算，或用固定 400px）
3. `window.set_size(LogicalSize::new(capsule_width, CAPSULE_HEIGHT))`
4. `window.set_min_size(Some(LogicalSize::new(CAPSULE_MIN_WIDTH, CAPSULE_HEIGHT)))`
5. `config` 写入 `layout_mode = "capsule"`

`leave_capsule_mode` 流程：
1. 读取 `compact_geometry`（Phase 1 保存的正常尺寸）
2. 恢复窗口尺寸和最小尺寸约束
3. `config.layout_mode = "compact"`

#### `AppConfig` 新增字段

```rust
#[serde(default = "default_capsule_x")]
pub capsule_x: Option<f64>,
#[serde(default = "default_capsule_y")]
pub capsule_y: Option<f64>,
```

胶囊位置与普通窗口位置分开存储，避免展开/折叠时位置互相干扰。

#### `App.tsx` 集成

新增状态：`capsuleMode: boolean`

```ts
const [capsuleMode, setCapsuleMode] = useState(
  config.layout_mode === 'capsule'
);
```

渲染逻辑：
```tsx
{capsuleMode ? (
  <CapsuleView
    tabs={openTabs}
    activeZone={activeZone}
    activeName={activeNote}
    onSelectTab={handleSelectTab}
    onNewNote={handleNewNote}
    onExpand={handleLeaveCapsule}
  />
) : (
  <CompactView ... />
)}
```

胶囊模式下整个 WebView 就是 `CapsuleView`，不渲染 `CompactView` 和资料库。

#### 无边框拖动

胶囊条需整体可拖动（除按钮区域外）。复用 `FloaterView` 已有的 `startDragging()` + 点击/拖动区分逻辑，封装为 hook `useDraggableBar`。

#### 过渡动画

折叠/展开由 Rust 侧直接调整窗口尺寸，WebView 内容用 CSS `transition: opacity 150ms` 淡入淡出，避免内容在小尺寸窗口中撑出怪样。

### 涉及文件（Phase 1）

| 文件 | 改动 |
|------|------|
| `src/components/CapsuleView.tsx` | **新文件**：胶囊条 UI 组件 |
| `src/App.tsx` | `capsuleMode` 状态、`enter/leaveCapsule` 处理函数、渲染分支 |
| `src-tauri/src/system.rs` | `enter_capsule_mode`、`leave_capsule_mode` 命令 |
| `src-tauri/src/lib.rs` | `AppConfig` 新增胶囊位置字段，注册两个新命令 |
| `src/App.css` | `.capsule-view` 样式，胶囊条布局 |
| `src/styles/tokens.css` | 胶囊相关 token（高度、圆角） |

### 验证方式（Phase 1）
1. 点击折叠按钮，窗口缩小为胶囊条
2. 胶囊条正确显示所有 Tab 标题，当前活跃 Tab 高亮
3. 点击某 Tab 标题，展开后切换到对应 Tab
4. 拖动胶囊条，位置正常跟随
5. 展开后窗口恢复到折叠前的尺寸和位置
6. 重启应用后，若上次是胶囊态，恢复胶囊态

## Phase 2：贴边吸附

> 依赖 Phase 1 完成

### 目标

- 胶囊模式下，松开拖动时检测距离左/右/上屏幕边缘的距离
- 若距离 < 阈值（如 80px），自动滑到对应边缘
- 贴边后窗口部分滑入屏幕外（只露出 8px 把手）
- 鼠标移入把手区域（`WM_MOUSEMOVE` hover）时，窗口滑出到完整可见位置
- 鼠标离开后，延迟 1.5s 再次滑入

### 方案设计

#### 边缘吸附（Rust + Win32）

在 `system.rs` 新增 `snap_capsule_to_edge`：

```rust
pub fn snap_capsule_to_edge<R: Runtime>(
    window: &WebviewWindow<R>,
    edge: SnapEdge, // Left | Right | Top
) {
    // 获取显示器工作区
    // 计算贴边后的目标坐标（partial_offset = 8px 把手）
    // window.set_position(...)
    // 启动 hover 监听
}
```

监听鼠标位置：通过后台线程轮询 `GetCursorPos`（Win32），判断是否在把手 8px 区域内，控制滑入/滑出动画。

动画实现：Tauri 侧通过循环 `set_position` + `std::thread::sleep(16ms)` 实现帧动画（60fps 级别的位置插值），或发送事件给前端，由前端 CSS 动画驱动（前端方案更流畅但需要窗口透明区域配合）。

#### 多显示器支持

使用 `MonitorFromWindow` + `GetMonitorInfo` 获取当前所在显示器的工作区，基于该工作区计算贴边坐标。

#### `AppConfig` 新增

```rust
#[serde(default)]
pub capsule_snap_enabled: bool,   // 默认开启
#[serde(default)]
pub capsule_snap_edge: Option<String>, // "left" | "right" | "top"
```

### 涉及文件（Phase 2）

| 文件 | 改动 |
|------|------|
| `src-tauri/src/system.rs` | 贴边逻辑、hover 监听、滑入/滑出动画 |
| `src-tauri/src/win_present.rs` | 复用/扩展现有 Win32 窗口操作 |
| `src-tauri/src/lib.rs` | `AppConfig` 新增贴边配置字段 |
| `src/components/CapsuleView.tsx` | 贴边把手渲染（8px 露出时的视觉提示） |

### 验证方式（Phase 2）
1. 拖动胶囊条到屏幕左侧 60px 以内松手，胶囊自动贴边，露出 8px
2. 鼠标移到把手区域，胶囊滑出
3. 鼠标离开 1.5s 后，胶囊滑回
4. 多显示器：拖到第二屏左边缘，正确贴到第二屏

## 风险与注意事项

- **窗口高度下限**：Tauri 的 `set_min_size` 需在切换前调整，否则 `set_size` 可能被夹住（当前 `COMPACT_MIN_HEIGHT = 440`，胶囊只需 44）
- **无边框窗口拖动**：`startDragging()` 在 Windows 上有已知边界（拖动中无法实时获取位置），Phase 2 的贴边检测需在 `dragend`（`pointerup`）时采样最终位置
- **WebView 最小宽度**：浏览器引擎对极小窗口的渲染有下限，胶囊 40px 高度在 WebView2 上需实测
- **内存占用**：折叠为胶囊后 WebView 进程仍运行，仅视觉缩小；若需真正的低内存胶囊，需用原生 Win32 窗口方案（复杂度大幅上升，本期不考虑）
- `FloaterView` 的迷你浮条可在 Phase 1 完成后考虑废弃或合并，避免两套"收缩态"并存
