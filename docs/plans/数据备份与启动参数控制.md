# Plan：数据备份 + 启动参数控制

> 状态：草稿
> 优先级：高（低风险、高收益，可独立完成）

---

## 背景

### 数据备份

当前 `notes.rs` 的 `write_note` 直接覆盖写 `.md` 文件，没有任何备份。异常退出（断电、崩溃）会导致写一半的文件损坏，且无法恢复。

### 启动参数控制

当前 `tauri-plugin-single-instance` 只在二次启动时把窗口拉到前台，没有解析任何参数。用户无法通过外部快捷键工具（AutoHotkey、PowerToys Run 等）精细控制窗口状态或快速新建笔记。

---

## 目标

### 数据备份
- 写笔记前自动把旧文件备份一份，异常时可手动恢复
- 不影响现有读写流程，无性能可感知开销

### 启动参数控制
支持以下 CLI 参数（程序已运行时第二个实例把参数转发给第一个实例）：

| 参数 | 行为 |
|------|------|
| `--show` | 显示窗口 |
| `--hide` | 隐藏窗口到托盘 |
| `--toggle` | 有则隐藏，无则显示 |
| `--new-note` | 显示窗口并新建一条普通笔记 |
| `--new-inbox` | 显示窗口并新建一条 Inbox 笔记 |

---

## 方案设计

### 数据备份

**策略**：写前原子备份，单文件粒度，不额外占用目录结构。

备份文件命名：`<name>.md.bak`，与笔记同目录存放。

```
File/default/
├── 20250101120000000.md       ← 主文件
├── 20250101120000000.md.bak   ← 上一次写入前的备份
```

**写流程**（`notes.rs::write_note`）：
1. 若 `<name>.md` 已存在，先 `fs::copy` 到 `<name>.md.bak`（覆盖旧 bak）
2. 再 `fs::write` 写主文件
3. 任一步失败都返回 `Err`，不静默忽略

备份文件不出现在 `list_notes` 结果里（过滤 `.bak` 后缀，已有的 `.md` 过滤逻辑在 `notes.rs::list_zone` 中扩展即可）。

**恢复**：本期不做 UI，保留文件供用户手动恢复。后续可在设置页加「从备份恢复」入口。

### 启动参数控制

**入口**：`lib.rs` 中的 `tauri-plugin-single-instance` 回调。

当前代码大致为：
```rust
app.plugin(tauri_plugin_single_instance::init(|app, _argv, _cwd| {
    // 目前仅显示窗口
    system::show_main_window(app);
}))
```

改为解析 `argv`：
```rust
app.plugin(tauri_plugin_single_instance::init(|app, argv, _cwd| {
    handle_cli_args(app, &argv);
}))
```

新增 `system.rs::handle_cli_args`：
```rust
pub fn handle_cli_args<R: Runtime>(app: &AppHandle<R>, argv: &[String]) {
    let args: std::collections::HashSet<&str> =
        argv.iter().map(|s| s.trim_start_matches('-')).collect();

    if args.contains("hide") {
        hide_main_window(app);
    } else if args.contains("toggle") {
        toggle_main_window(app);
    } else if args.contains("new-note") || args.contains("new-inbox") {
        show_main_window(app);
        // 发送事件给前端，由前端调用 create_note
        let zone = if args.contains("new-inbox") { "inbox" } else { "default" };
        if let Some(window) = main_window(app) {
            let _ = window.emit("mknote:new-note", zone);
        }
    } else {
        // --show 或无参数，默认显示
        show_main_window(app);
    }
}
```

前端在 `App.tsx` 中监听 `mknote:new-note` 事件，调用现有的 `handleNewNote(zone)` 逻辑。

**首次启动（无运行实例）时的参数处理**：Tauri 2 的 `tauri::Builder` 支持 `setup` 阶段读取 `app.get_cli_args()`（需在 `tauri.conf.json` 的 `cli` 字段声明参数）。可选择本期只处理"已有实例转发"的场景，首次启动参数留到下个迭代。

共 4 个文件，改动集中、互不耦合。

## 验证方式

### 数据备份
1. 打开一条笔记，写入内容保存
2. 查看同目录是否生成 `<name>.md.bak`，内容为上一次的版本
3. 再次修改保存，确认 `.bak` 更新为上一版
4. `list_notes` 结果中不含 `.bak` 文件

### 启动参数控制
1. 运行应用后，在终端执行 `MKnote.exe --hide`，窗口应隐藏到托盘
2. 执行 `MKnote.exe --show`，窗口应显示
3. 执行 `MKnote.exe --toggle`，重复两次验证切换行为
4. 执行 `MKnote.exe --new-note`，窗口显示且新建一条笔记

## 风险与注意事项

- `.bak` 文件与主文件同目录，需确认 `agent_index` 和 `list_notes` 的过滤逻辑已覆盖（搜索 `.md` 后缀过滤处）
- `single-instance` 参数转发在应用**已运行**时才生效；首次冷启动的参数解析是另一个机制，本期不做
- Windows 快捷方式可直接用 `目标: "C:\...\MKnote.exe" --new-note` 的形式调用
