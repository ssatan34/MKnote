# MKnote UI v2 实现说明

更新时间：2026-10-20

v5.2.4 整合 Quick 数据目录、外部文件自动刷新、Allnote Work 项目分组与多层任务、自动任务只读保护，以及来源笔记和项目主页入口；保留 5.2.3 多行转待办与 Tab 路径复制。外部轮询不重叠在途读取，写入排队时延后刷新；内容相同不替换列表状态。

v5.2.3 多行转待办已通过用户验收。文本与可视化编辑均支持选中多行后逐行生成待办；保留空行、已有任务及完成状态，自动折行不拆分，无选区保留原单行操作。顶层纯任务列表取消额外缩进，并保留与后续段落的间距。混合列表、普通列表及嵌套层级缩进保持原规则。见 [RELEASE-5.2.3.md](RELEASE-5.2.3.md)。

v5.2.2 Tab 右键复制笔记路径已通过用户验收。支持常规、置顶及置顶「更多」列表，复制完整目录、文件名和扩展名。发布与验证见 [RELEASE-5.2.2.md](RELEASE-5.2.2.md)。

v5.2.1 置顶栏与 Tab 切换优化已通过用户验收：独立底栏不遮挡正文、标题按实际宽度显示、条件整栏高亮、激活尺寸稳定；切换保留保存与首次备份保护。发布与验证见 [RELEASE-5.2.1.md](RELEASE-5.2.1.md)。

v5.2.0 新增 Jev 自动归类与 AI 助手双 Tab 设置，统一表单、主题色开关和候选文件夹卡片；中键关闭只触发一次，空白笔记不调用 Jev。

v5.1.0 上传设置使用统一卡片、主题色开关、内联目录选择和保存按钮；思源 / Obsidian 选项卡互斥启用，也可全部关闭。上传成功仅高亮对应按钮 2 秒，不再展示成功文字浮层；失败仍显示错误。左上角 Logo 默认无底色及边框，保留悬浮反馈；应用内和系统各处均使用透明羽毛母版导出。

本文描述当前 UI 状态。历史上的独立展开管理台已不再作为主流程，资料库已整合进默认编辑界面。

## 窗口

| 项 | 当前状态 |
|----|----------|
| 默认形态 | 默认编辑界面 |
| 资料库 | 通过底部状态栏按钮展开/收起 |
| 隐藏后恢复 | 普通笔记恢复默认编辑界面；待办事项恢复待办界面 |
| 浮标 | 点击左上 logo 可进入/退出 logo mini |

从隐藏、托盘或快捷键再次显示窗口时，前端会重置为：

- 资料库收起。
- 浮标关闭。
- 颜色筛选清空。
- 编辑模式。
- 若隐藏前是 `待办事项.md`，恢复待办事项界面；否则恢复普通 Markdown 编辑界面。

窗口形态由窗口 label 选择：主窗口使用 `CompactView`，独立便签窗口和胶囊窗口分别使用 `PopoutView` / `CapsuleView`。

## 存储目录

| 区域 | 默认路径 |
|------|----------|
| Inbox | `{base}/inbox` |
| Default | `{base}/File/default` |
| 新建文件夹 | `{base}/File/<folder-name>` |

`{base}` 取可写的 `executable_dir`，失败时回退到 `current_exe` 父目录；绿色版必须放在可写目录中运行。

## 便签文件

- 新建：`YYYYMMDDHHmmssSSS.md`。
- 标题显示：文件名去 `.md`。
- 改标题：重命名 `.md` 文件；非法字符过滤；冲突加随机后缀。
- 每条便签仍是独立 Markdown 文件。
- 颜色标签不写入 Markdown 正文，保存在 `File/.mknote-note-colors.json`。

### 底部状态栏

状态栏上方有独立占位的单行置顶笔记栏（2026-10-10 用户验收通过）：

- 横向使用整行可用宽度，无置顶笔记时不占高度；资料库展开时仍可切换置顶笔记。
- 置顶标题按内容宽度显示，单项最大 220px，超出时省略；悬停显示完整标题。
- 仅当前笔记属于置顶笔记时，置顶栏显示主题色浅底与顶部强调线；普通笔记激活时恢复普通底色。每个 Tab 使用独立底色、细边框，选中项加深底色并突出轮廓；激活前后宽度限制保持一致。
- 置顶栏与第一个 Tab 的左边界对齐编辑工具栏的右边界，不显示独立置顶图标。
- 放不下的置顶笔记进入「更多 N」，菜单显示完整标题；选择后当前项进入可见区域，不改变保存的置顶顺序。
- 正文滚动区域在置顶栏上方结束；源码与可视化编辑均不被遮挡。
- 保留拖动排序、拖出窗口、中键关闭及置顶关闭确认。
- 常规 Tab、置顶 Tab 与置顶「更多」列表共用右键菜单，提供「复制笔记路径」。复制针对右键点中的笔记，无需切换当前笔记；使用实际笔记目录与原始文件名（含扩展名），失败时显示错误提示。

状态栏包含：

## Jev 自动归类（v5.2.0，2026-10-02 用户验收通过）

- 设置 → AI 配置分为「AI 助手」与「Jev 自动归类」两个 Tab，切换保留未保存的表单；Jev 使用统一主题色开关、输入控件、候选文件夹卡片和保存按钮。Jev Tab 提供：启用开关、模型来源、该来源 API Key 与模型、已有候选文件夹及可选用途说明、测试连接和保存。
- 官方默认为 `jev-latest`，Command Code 默认为 `typesafe/jev`；切换来源保留各自配置，密钥沿用 Windows DPAPI 保存。接口分别参考 [TypeSafe 官方文档](https://docs.typesafe.ai/api) 和 [Command Code 文档](https://commandcode.ai/docs/provider)。
- 状态栏 AI 图标按钮手动归类当前 Default 普通笔记。先保存最新正文，再调用模型并移动文件，同时更新打开的 Tab；其他区域、隐私笔记和专用默认便签禁用。
- 中键关闭 Tab（包含确认关闭置顶 Tab）和「关闭其他标签」：保存后将空白笔记移入回收站；非空 Default 普通笔记关闭后后台归类。隐藏到托盘、独立便签或胶囊关闭不触发。
- 笔记移回 Default 后重新成为待归类笔记。候选只包含用户勾选的现有自定义文件夹，不创建新文件夹。
- 模型失败、候选失效或正文被修改时保留原位置并显示错误；后台响应返回时已重新打开的笔记跳过本次归类。
- 现有最后一个 Tab 不允许关闭的规则保持不变。专用根目录默认便签不参与自动删除或归类。

## 内嵌资料库

资料库由两列组成：

- 左列：文件夹 + 颜色标签筛选。
- 右列：当前文件夹笔记列表。

### 文件夹

- `Inbox` 与 `Default` 为默认文件夹。
- 新建文件夹位于 `File/<folder-name>`。
- 文件夹可新建。
- 文件夹可双击重命名；`Default` 不可重命名。
- 不提供删除文件夹按钮，避免误删。
- 文件夹前置 icon 已移除。
- 文件夹颜色设置已取消。
- 文件夹点击只切换列表，不打开资源管理器。

### 笔记列表

- 右上 `+` 在当前文件夹中新建笔记。
- 单击打开笔记。
- 双击笔记条目，在鼠标位置弹出输入框重命名。
- 拖拽笔记到其他文件夹可移动文件。
- 删除使用小号二次确认：
  - 首次点 `x` 进入确认态。
  - 点 `√` 确认删除。
  - 点 `x` 取消。

### 笔记颜色标签

- 每条笔记左侧固定显示颜色圆点。
- 已设置时显示对应颜色。
- 未设置或清除后显示透明占位圆。
- 点击左侧圆点可选择 5 种颜色或用 `x` 清除。
- 右侧不再显示颜色标签按钮。

### 颜色筛选

- 文件夹栏下方固定显示 5 种颜色标签（纵向：色点 + 名称 + 全库数量）。
- 数量为全库统计；计数为 0 时不显示数字。
- 点击某标签后，右侧列表显示**全库**同色笔记，并标注所在文件夹。
- 再次点击同色或点击清除按钮可取消筛选。
- 外观设置中可自定义各标签显示名称（`config.note_color_labels`）。

## Quick Pocket 分组交互规格

Quick Pocket 的基本单位仍是“标题 + 内文”的单个条目；分组只保存条目之间的归属关系，不改变条目内容、标签或隐私状态。

### 分组约束

- 分组只支持一层，不支持嵌套。
- 分组至少包含 2 个条目，不允许空分组。
- 分组名允许重复。
- 解散分组不删除条目，条目回到未分组列表。
- 分组内条目被拖出，或删除条目后分组只剩 1 个条目时，自动取消分组，剩余条目回到未分组列表。
- 不提供单独的“添加分组”按钮，也不提供批量加入分组功能。

### 分组标题栏

从左到右依次为：

`拖拽放置区域` → `展开/折叠` → `组名` → `条目数量` → `在此分组中新建条目` → `解散分组`

- 双击组名直接重命名，不增加独立的重命名按钮或二级菜单。
- 分组整体可以通过左侧拖拽放置区域拖动。
- 分组拖拽手柄使用当前主题强调色；分组整体使用同色系细轮廓线，将组内条目在视觉上连成一个单元。
- 分组标题栏采用约 20px 的紧凑行高，组名、数量和图标按该高度独立缩放，保持清晰且充分利用纵向空间。
- 分组作为一个复合列表条目参与统一排序，不单独置顶；普通条目可以位于分组上方、下方或两个分组之间。
- 不显示“已分组”或“未分组”分区标题。
- 条目数量、组内新建、解散分组三个控件组成固定右侧操作区。
- 分组折叠状态保存在前端状态中，并持久化。

### 条目拖拽与建组

两个未分组条目互相拖拽重叠时，按目标条目整体高度判断放置意图：

- 上 25%：显示目标条目上方插入线，松开后移动到目标之前。
- 下 25%：显示目标条目下方插入线，松开后移动到目标之后。
- 中间 50%：显示分组提示，松开后由两个未分组条目创建新分组。

创建新分组后，在顶部工具栏下方水平居中显示组名输入框。输入区复用资料库“新建文件夹”的下划线输入框与 `Add` 按钮样式；按 Enter 或点击 `Add` 创建分组，按 Escape、失焦或点击遮罩取消并恢复拖拽前的顺序和归属，空白名称不创建。

- 拖入已有分组的条目时，加入该条目所属分组，不创建嵌套分组。
- 只有两个未分组条目之间保留上 25% / 中间 50% / 下 25% 的建组判断。
- 同一分组内拖拽、组外条目拖入分组、分组内条目拖出或跨组移动均只使用上半区/下半区排序，不显示中间建组区域。
- 从一个分组拖到另一个分组时，条目移动到目标分组；原分组只剩 1 个条目时自动取消分组。
- 分组整体拖拽用于移动整组位置，不改变组内条目顺序和成员关系。
- 组内新增入口只保留在分组标题栏，不在分组内容底部重复显示。

### 标签筛选

- 标签筛选忽略分组结构，结果以扁平条目列表显示，不显示分组标题、数量或折叠状态。
- 标签筛选期间暂时禁用跨分组拖拽；筛选状态只用于查看，不改变分组归属。

## Quick Pocket 多实例设计决策（已采纳，v4.1.3 分支实现）

Quick Pocket 后续支持多个相互独立的 Pocket。现有默认 Pocket 保持兼容，不迁移、不改名、不改变现有使用方式。

### Pocket 身份与数据

- 默认数据目录为 `inbox`，其中 `Quick Pocket.md` 作为默认 Pocket，内部 ID 为 `default`；可在设置中指定其他数据目录。
- 新建 Pocket 创建一个全新的 Markdown 文件；文件使用稳定 `pocket_id` 命名，不使用可变显示名称作为身份。
- Pocket 之间分别保存条目、顺序、分组、标签和窗口状态，不支持第一阶段的跨 Pocket 拖拽或移动。
- Pocket 的显示名称与内部 ID 分离；若暂时没有重命名入口，初始显示名称可直接使用 ID。

### 打开入口

- 项目设置新增 Quick Pocket 管理板块，负责新建、命名和删除 Pocket。
- Pocket 显示名称最多 6 个字符；默认 Pocket 固定为“Quick Pocket”，不允许重命名或删除。
- 现有 Quick Pocket 按钮点击后显示紧凑弹出式 Pocket 选择器，选择器只提供打开默认 Pocket 或已有 Pocket。
- 选择某个 Pocket 后，打开与其 ID 对应的独立窗口；窗口 UI 和交互完全复用默认 Pocket。
- 默认 Pocket 仍使用现有文件和数据格式，不能因为新增 Pocket 而触发迁移或重写。

### 实现边界

- 后端 command、变更事件、窗口 label、窗口几何、置顶和锁定配置均按 `pocket_id` 隔离。
- 新 Pocket 的分组规则继续遵循本节既有的单层分组约束。
- 第一阶段不做跨 Pocket 搜索、合并、批量导入和跨 Pocket 拖拽。
- CLI/YASB 的按 Pocket 独立入口作为后续扩展，不作为 Pocket 基础能力的前置条件。

## Quick Todo 多实例设计决策（已实现）

### Allnote Work 分组视图（2026-10-13）

- Work 内的 Allnote 自动任务使用 `allnote_work_` ID 与 `allnoteWork` v1 元数据。按真实项目路径折叠分组，同名项目不合并；任务按真实 `parentId` 多层缩进，不把标题或项目名当作任务。
- 已完成父任务可作为上下文显示，不计入待处理数量。日期独立放在任务下方；项目按钮优先打开项目主页，来源按钮打开实际工作笔记，均通过受限的 Allnote URI 原生入口。
- 自动任务不提供编辑、完成、删除、标签、提醒和拖拽；Rust 写接口同样拒绝修改。手工任务位于独立区域，保留原操作；排序与清理已完成仅作用于手工任务。
- 默认个人列表保持原显示与写入规则；项目折叠状态在当前窗口外部刷新时保留。

Quick Todo 复用多 Quick Pocket 的身份、管理和打开模型，同时保留现有默认 Todo 的文件与使用方式。

### Todo 身份与数据

- 默认数据目录为 `inbox`，其中 `Quick Todo.md` 作为默认 Todo，内部 ID 为 `default`，不自动迁移、不改名；可在设置中指定其他数据目录。
- 新 Todo 使用稳定 `todo_id` 创建独立 Markdown 文件，显示名称与 ID 分离；显示名称最多 6 个字符。
- Todo 之间分别保存条目、父子关系、顺序、标签、提醒和窗口状态，不支持跨 Todo 拖拽或移动。
- 默认 Todo 不允许重命名或删除；删除非默认 Todo 时同时删除对应文件，失败时恢复配置和文件。

### 打开入口

- 设置 → 系统 → Quick Todo 管理负责创建、重命名和删除 Todo。
- 状态栏 Quick Todo 按钮打开紧凑选择器；选择已有 Todo 后打开对应独立窗口。
- 独立窗口继续复用 Quick Todo Panel/controller，标题显示对应 Todo 名称。
- CLI/YASB 可用 `--quick-todo=<todo_id>` 或 `--toggle-quick-todo=<todo_id>` 直达指定 Todo；省略 ID 时保持默认 Todo 行为。

### 实现边界

- 后端 command、变更事件、窗口 label、提醒窗口、窗口几何、置顶和锁定配置均按 `todo_id` 隔离。
- 默认 Todo 的 S3 对象保持兼容；非默认 Todo 和 Todo 注册表使用独立对象 Key。
- 本次不增加跨 Todo 搜索、合并、批量导入或跨 Todo 拖拽。

## Quick 数据目录（2026-10-13）

- 设置 → 系统 → Quick Todo / Quick Pocket 各提供一个数据目录输入框、原生目录选择与保存按钮；可以分别指定目录，也可以指向同一 Allnote 目录。
- 默认列表分别保存为所选目录下的 `Quick Todo.md`、`Quick Pocket.md`；其他列表保留 `Quick Todo/<todo_id>.md`、`Quick Pocket/<pocket_id>.md` 结构。列表名称、注册表和窗口状态仍保存在应用配置中，不按目录扫描导入未知 ID。
- 留空并保存使用程序默认 `inbox`。指定目录必须已存在；旧配置无需修改即可沿用原路径。
- 保存后需完全退出并重启才生效；设置页显示当前使用目录和待重启提示。运行期间固定路径，避免已打开编辑器或同步任务跨目录提交旧内容。
- 所有 Quick 读取、保存、新建、删除和 S3 同步共用路径解析；远端对象 Key 保持原契约，绝对目录不随注册表同步到其他设备。
- 保存设置不会移动、复制或删除原文件；切换到空目录后，打开或编辑 Quick 列表会按原逻辑新建数据文件。普通便签路径保持不变。

## 主题与外观

### Tab 切换响应

- 激活 tab 的颜色和底色即时更新，hover 使用 100ms 过渡；正文切换不使用淡入或位移动画。
- 已打开 tab 的颜色元数据直接复用现有缓存，切换前不再重复扫描笔记列表。
- 普通笔记首次进入可视化编辑器仍等待迁移备份确认；同一窗口运行期间仅复用成功结果，失败不缓存，重新启动后再次确认。
- 未保存内容仍须保存成功后才能切换；保存失败或冲突时停留在当前笔记，不清除脏内容。
- 切换前同步收取可视化编辑器尚未上报的最后输入，避免 200ms 输入上报防抖遗漏；连续点击以最后一次选择为准。

当前支持：

- 明暗模式：跟随系统 / 浅色 / 深色。
- 主题样式：MKnote、Catppuccin、Hermes、Poseidon、Ares、Nous、Midnight、Ember、Mono、Slate、GBF。
- Midnight、Ember、Mono、Slate、GBF 以深色调色板为设计基准，浅色模式使用合成色板。

主题入口：

- 顶栏明暗模式快捷按钮。
- 顶栏外观设置按钮。

## 待办事项模板

- 首次启动自动创建 `待办事项.md`。
- 点击左下工具栏待办入口打开。
- 该笔记始终使用专用待办界面，不显示源码编辑模式。
- 默认两列：`工作`、`私人`。
- 列标题可编辑。
- 列标题旁 `+` 创建父级待办。
- 父级待办右侧 `+` 创建二级子事项。
- 子事项不显示 `+`。
- 父级和子级均支持标题、内文、完成状态。
- 新建任务默认进入标题输入；空标题失焦后自动删除。
- 标题双击编辑，单击展开/收起详情。
- 空正文可点击进入详情编辑。
- 正文编辑区自增长，不出现内部滚动条。
- 标题与正文长文本自动换行。
- 未完成任务 hover 1 秒显示创建时间。
- 已完成任务 hover 1 秒显示完成时间。
- 已完成事项超过 7 天自动清理。
- 父级可拖拽移动位置或移动到其他列；父级也可拖到其他父级卡片/标题区域成为子级。
- 子级可拖拽到其他父级下，也可拖到父级列表横线或底部横线成为父级。
- 拖拽时横线表示排序/升为父级，父级卡片高亮表示归入该父级。
- 底层保存为 Markdown，任务元数据写入 HTML 注释。
