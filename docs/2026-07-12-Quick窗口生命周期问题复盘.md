# Quick Todo / Pocket 窗口生命周期 Bug 复盘

- 日期：2026-07-12
- 范围：Quick Todo、Quick Pocket 独立窗口的失焦关闭、缩放稳定性、Todo 重开视图与窗口拖动
- 状态：已解决并经用户验收

## 一句话结论

Quick 窗口不能同时依赖 Tauri `Focused(false)` 与跨 WebView 事件；前者在 Windows 的缩放和部分焦点切换中不稳定，后者未可靠抵达目标 WebView。最终改为 Windows 顶层窗口前台监控直接保存/隐藏，并以浏览器 `focus` 重置 Todo 视图；同时补齐 Quick 窗口拖动 capability。

## 现象

1. Todo/Pocket 失去焦点后不关闭，或某些版本在首次打开时闪现后立即关闭。
2. 调整窗口尺寸时，窗口曾逐渐消失。
3. Todo 切到“已完成”后，关闭再打开仍停留在已完成页。
4. 在生命周期修复后，两个窗口顶部拖动报错：`window.start_dragging not allowed on window "quick-todo"` / `"quick-pocket"`。

## 根因

| 层级 | 根因 | 证据 |
|---|---|---|
| Tauri 窗口事件 | `WindowEvent::Focused(false)` 在非客户区缩放与部分 Windows 焦点切换中不是稳定的业务信号。 | 直接用该事件关闭会在缩放时误隐藏；加延迟后又出现实际失焦不关闭。 |
| Win32 句柄 | WebView2 可能返回子句柄，而 `GetForegroundWindow`、可见性和最小化判断使用顶层句柄。 | 将检测统一提升到 `GA_ROOT` 后，原生监控能观测到 Quick 窗口前台状态。 |
| 跨 WebView 通信 | `window.emit(...)` 的 Quick 窗口事件未可靠抵达 Quick Todo/Pocket 的前端监听器。 | 原生监控已记录失焦请求，但目标窗口仍保持可见；Todo 的重开视图事件亦未生效。 |
| Capability | `default.json` 的窗口列表不含 `quick-todo`、`quick-pocket`。 | 截图中的 Tauri 错误明确列出了 capability windows 白名单。 |

## 解决办法

1. 在 `src-tauri/src/win_present.rs` 新增根 HWND 解析，将呈现和前台判断统一基于 `GA_ROOT`。
2. 在 `quick_todo_window.rs`、`quick_pocket_window.rs` 为每个 Quick 窗口启动 50ms 原生前台轮询；确认曾处于前台且连续 150ms 离开前台后，直接执行 `save_and_hide`。
3. 删除依赖跨 WebView 的失焦隐藏请求；输入控件的自身 blur 先保存草稿，原生隐藏在防抖期后发生。
4. Todo 用浏览器 `focus` 事件重置为待办视图，避免跨窗口打开事件。
5. 在 `src-tauri/capabilities/default.json` 将 `quick-todo` 与 `quick-pocket` 纳入拥有 `core:window:allow-start-dragging` 的 capability。

## 验收与回归

用户已验证：

- Todo/Pocket 点击主窗或其他窗口后自动关闭。
- 调整窗口尺寸时不消失。
- Todo 从已完成页关闭再打开，回到待办页。

自动验证：

```powershell
npm.cmd run test:quick-todo   # 37 passed
npm.cmd run test:quick-pocket # 6 passed
npm.cmd run build
cargo check --manifest-path src-tauri\Cargo.toml
```

## 后续约束

- 不要恢复 `Focused(false)` 直接关闭窗口的实现。
- 不要把 Quick 窗口的关键业务状态建立在跨 WebView `window.emit` 上；若必须通信，先做实际多窗口验收。
- 新增独立窗口调用原生 API 时，必须同步检查 `src-tauri/capabilities/default.json` 的窗口匹配范围。
