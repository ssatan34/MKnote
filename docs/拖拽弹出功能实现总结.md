# Tab 拖拽弹出新窗口功能实现总结

## 功能概述

实现了类似 Microsoft Edge 的 Tab 拖拽弹出功能：用户向上拖拽 Tab 超出窗口边界后松手，该 Tab 会弹出为独立窗口，且新窗口左上角精准定位到鼠标松手位置，实现无缝的拖拽体验。

---

## 用户需求

### 初始问题
右键菜单 →「在新窗口中打开」操作链路过长（3 步），希望通过拖拽快速实现。

### 优化需求（三次迭代）

**第一版问题**：
1. **视觉反馈不明显**：拖出时 Tab 只有轻微透明度变化，难以判断是否触发弹出
2. **判定区域太远**：需要拖出窗口 40px 才触发，体验不够直观
3. **新窗口位置随机**：与鼠标松手位置无关，用户需要再次拖动调整位置

**最终优化方案（全采纳）**：
1. **视觉增强**：Tab 向上飘起 + 放大（`translateY(-8px) scale(1.05)`），opacity 提升到 0.85
2. **判定优化**：拖出边界即触发（`clientY < 0`），无需拖远
3. **位置跟随**：新窗口左上角定位到鼠标屏幕坐标，松手后鼠标刚好在标题栏上，可无缝继续拖动

## 技术实现

### 1. 前端拖拽检测（`NoteTabsBar.tsx`）

**状态管理**：
```typescript
// ref：不触发重渲染，供逻辑判断
const dragStartYRef = useRef(0);
const dragOutOfWindowRef = useRef(false);

// state：触发重渲染，供 CSS 类名
const [dragOutOfWindow, setDragOutOfWindow] = useState(false);
```

**拖拽边界判断**（`handlePointerMove`）：
```typescript
const outOfWindow = e.clientY < 0;  // 刚超出窗口上边界即触发
if (outOfWindow !== dragOutOfWindowRef.current) {
  dragOutOfWindowRef.current = outOfWindow;
  setDragOutOfWindow(outOfWindow);  // 触发 CSS 视觉反馈
}
```

**松手处理**（`finishDrag`）：
```typescript
if (dragOutOfWindowRef.current && didDragRef.current && from != null) {
  const tab = tabs[from];
  // 必须同步读取 screenX/screenY（React 事件池化问题）
  const mouseScreenX = e.screenX;
  const mouseScreenY = e.screenY;
  onPopoutTab(tab.zone, tab.name, mouseScreenX, mouseScreenY);
  return;  // 跳过原有的重排序逻辑
}
```

### 2. 坐标传递与转换（`App.tsx`）

**DPI scale 处理**：
```typescript
const handlePopoutTab = async (zone, name, screenX?, screenY?) => {
  const scale = await getCurrentWindow().scaleFactor();
  
  // 物理像素 → 逻辑像素（Tauri position 需要逻辑坐标）
  const logicalX = screenX != null ? screenX / scale : undefined;
  const logicalY = screenY != null ? screenY / scale : undefined;

  await invoke("open_note_popout", {
    zone, name, title, width, height,
    x: logicalX,
    y: logicalY,
  });
};
```

**为什么要除以 scale**：
- `e.screenX/screenY` 返回**物理像素**（如 1920 在 150% 缩放下实际是 2880 物理像素）
- Tauri `.position(x, y)` 接受**逻辑像素**（CSS 像素）
- 若不转换，150% 缩放下传 900 会被当成逻辑坐标，实际放到 `900 * 1.5 = 1350`，位置错误

### 3. Rust 窗口定位（`detach.rs`）

**命令签名扩展**：
```rust
pub async fn open_note_popout(
    app: tauri::AppHandle,
    zone: String,
    name: String,
    title: String,
    width: f64,
    height: f64,
    x: Option<f64>,      // 新增：窗口左上角 x（逻辑坐标）
    y: Option<f64>,      // 新增：窗口左上角 y（逻辑坐标）
) -> Result<(), String>
```

**窗口构建器应用坐标**：
```rust
let mut builder = WebviewWindowBuilder::new(&app, &label, url)
    .title(&title)
    .inner_size(w, h)
    .min_inner_size(400.0, 300.0)
    .decorations(false)
    .always_on_top(false)
    .resizable(true);

// 若提供了屏幕坐标（拖拽弹出时），设置窗口左上角位置
if let (Some(px), Some(py)) = (x, y) {
    builder = builder.position(px, py);
}
```

### 4. 视觉反馈（`NoteTabsBar.css`）

```css
/* 拖出窗口上边界时：向上飘起 + 放大，提示即将弹出新窗口 */
.note-tab.dragging.drag-out {
  opacity: 0.85;
  transform: translateY(-8px) scale(1.05);
  transition: opacity 0.15s, transform 0.15s;
}
```

- `translateY(-8px)`：向上飘 8px，方向暗示"向上弹出"
- `scale(1.05)`：放大 5%，暗示"即将独立成窗口"（而非缩小 = 消失）
- `opacity: 0.85`：半透明但不过分，保持可读性

### 5. 边界情况处理

**最后一个 Tab 被拖出**：
```typescript
// App.tsx - handlePopoutTab
if (activeNoteRef.current === name && activeZoneRef.current === zone) {
  const nextTab = getTabAfterClose(zone, name);
  if (nextTab) {
    void switchToTab(nextTab.zone, nextTab.name);
  } else {
    // 无其他 Tab 可切 → 切到默认便签
    void handleOpenDefaultNote();
  }
}
```

**右键菜单弹出保持原行为**：
- 右键菜单调用 `handlePopoutTab(zone, name)`（不传坐标）
- `x/y` 为 `undefined` 时，Rust 不调用 `.position()`，窗口使用系统默认位置（居中）

## 关键问题与解决

### 问题 1: 参数丢失 — `screenX/screenY` 传到 Rust 后变 `undefined`

**现象**：
```
[finishDrag] mouseScreenX=1044.67, mouseScreenY=248
[popout] screenX=undefined, screenY=undefined
```

**排查过程**：
1. ~~事件池化~~：尝试同步读取 `e.screenX/screenY` 到局部变量 → 仍 `undefined`
2. ~~热更新失败~~：完全重启 dev → 仍 `undefined`
3. **找到根因**：`App.tsx` 传给 `NoteTabsBar` 的 `onPopoutTab` 是内联箭头函数，只转发了前两个参数：
   ```typescript
   // ❌ 错误：丢弃了第 3、4 个参数
   onPopoutTab={(zone, name) => void handlePopoutTab(zone, name)}
   ```

**解决**：
```typescript
// ✅ 正确：直接传函数引用，自动转发所有参数
onPopoutTab={handlePopoutTab}
```

### 问题 2: DPI scale 导致位置偏移

**现象**：用户显示器 2560×1600 @ 150% 缩放，新窗口出现在鼠标左侧。

**根因**：
- `e.screenX` 返回物理像素（如 1500）
- Tauri `.position()` 需要逻辑像素（1500 / 1.5 = 1000）
- 不转换时窗口被放到 `1500 * 1.5 = 2250` 的位置

**解决**：
```typescript
const logicalX = screenX / scale;
```

### 问题 3: React 事件池化（已排除，但值得记录）

**初步怀疑**：`handlePopoutTab` 是 async 函数，`await` 后事件对象被 React 回收，`e.screenX` 变 `undefined`。

**排除原因**：同步读取后仍 `undefined`，说明问题不在事件池化，而在参数转发。

**教训**：虽然这次不是池化问题，但在 async 函数里访问事件属性**确实有风险**，养成"事件属性同步读取到局部变量"的习惯是好实践。

## 测试验证

✅ **拖拽重排序**：横向拖 Tab → 正常重排（原功能不受影响）  
✅ **拖出弹出**：向上拖超出窗口 → Tab 飘起放大 → 松手 → 新窗口出现在鼠标位置

## 技术要点总结

1. **`clientY < 0` 判定边界**：PointerEvent 的 `clientY` 相对窗口内容区，拖出上方时变负
2. **`setPointerCapture` 保证拖出仍收到事件**：即使拖到窗口外，`pointerMove` 仍能触发
3. **同步读取事件属性**：React 事件池化要求在 async 边界前提取 `e.screenX/screenY`
4. **物理像素 vs 逻辑像素**：高 DPI 下必须除以 `scaleFactor` 转换
5. **函数引用 vs 箭头函数**：`onPopoutTab={handlePopoutTab}` 自动转发所有参数，避免遗漏
6. **可选参数向后兼容**：右键菜单不传坐标时，Rust 侧用 `Option<f64>` 处理，不影响原有行为
